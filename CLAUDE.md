# CLAUDE.md

## Project

Personal portfolio site for Leo Succar (leo.dev). Stack:

- **TanStack Start** (React 19) — file-based routes in `src/routes/`, server-rendered on a **Cloudflare Worker** via `@cloudflare/vite-plugin`; TypeScript strict mode
- **Tailwind CSS 4** — configured in `src/styles.css` (`@theme`), no `tailwind.config.js`; shadcn-style `src/components/ui/` primitives on **Base UI**
- **Content in Cloudflare D1** (Drizzle ORM), **images in R2**, edited at **`/admin`** (a small built-in CMS behind Cloudflare Access). Sanity was removed on 2026-11-09
- **motion** (`motion/react`) — animations
- **pnpm**, exact-pinned versions. Nothing from Vercel (no Next.js, no `vercel` CLI, no `next-*` packages); keep it that way.

## Deployment and content freshness

- The site deploys as a Cloudflare Worker named `leodotdev` on the custom domain `leo.dev` (`wrangler.jsonc`; Cloudflare manages its DNS record); ship with `pnpm run deploy`. Static files in `public/` are served before the Worker runs (`html_handling: "none"`, so `/resume.html` stays reachable as is).
- Pages render per request and read D1 directly, so **edits made at `/admin` show up on the next page load**, with no rebuild or deploy.
- `pnpm dev` uses the **production** D1 database and R2 bucket (`remote: true` in `wrangler.jsonc`), like mdc: local admin edits are live.
- Workers runtime only: no Node `fs`; `nodejs_compat` is on. Use `cloudflare:workers` for `env`/`waitUntil`.

## Conventions

- Path alias `@/*` → `src/*` (configured in `tsconfig.json`)
- Routes: `createFileRoute`, data in `loader` via server functions; internal links use TanStack `Link` (`to="/projects/$slug"` + `params`), external links and static files use plain `<a>`
- Images: stored as `Img` records (`src/lib/image.ts`): WebP at 320/960/1920px in R2, named `<base>-<width>.webp`. Render with plain `<img {...imageProps(img, { maxWidth })}>` and pass `sizes`. Plain strings (files in `public/`, like the experience logos) pass through. Admin uploads are resized in the browser (`src/lib/resize.ts`); SVG uploads are refused (same-origin script risk)
- Fonts: `@fontsource-variable/inter` (body) and `@fontsource-variable/playfair-display` (`font-playfair`), imported in `src/styles.css`, and Paper Mono (`font-mono`; `public/fonts/paper-mono-variable.woff2`, open source, licence beside it) for all 12px text
- Type scale: only `text-xs` (12px, which also sets Paper Mono) and `text-base` (16px, Inter) exist; other `text-<size>` classes are no-ops
- Colors: the whole site wears the Claude.com design system's palette (`src/claude-ds.css`; the site's tokens in `src/styles.css` point at it): the White theme in light mode and Dark 3 in dark mode. Tailwind's own palette is switched off, so `blue-500`, `zinc-200` and the like are no-ops. Use the accent (`text-tint`: the system's switch blue, `#2c84db`, everywhere except `/work/claude`, where it is Clay), Clay itself (`clay`) and the secondary colors (`heather`, `cactus`, `peach`, `plum`, `mineral`, `sky`, as in `bg-peach/40`), `error`, the greys (`gray`, `gray-2` … `gray-6`) and the roles built on them (`bg-background`, `bg-card`, `text-muted-foreground`, `border-border`). The neutrals follow the theme, so `dark:` variants are only needed for a tint's opacity. The layout overlay is the palette's switch blue on every page, `/work/claude` included (`--color-grid`)
- Formatting: Prettier, no semicolons (`pnpm format`; `pnpm check` to verify)
- Titles: a title, name or label joins its parts with `&`, not "and" ("Headers & Footer", "Checkbox, Radio & Switch"). Sentences keep "and"
- Lists in copy take the serial (Oxford) comma: "navigation, prompt suggestions, and lists"
- Focus: one rule at the end of the base styles in `src/styles.css` outlines whatever has keyboard focus (2px, the accent color, 2px off). Do not add focus rings to components; a box that clips its children (`overflow-hidden`, a scrolling row) needs 4px of padding for the outline
- Text blocks on the docs pages end on a column edge: `max-w-cols-9` (9 of 12 columns, 6 of 8 on a tablet). The layout overlay's columns have 24px gutters and 48px margins (24px on a phone)
- Waves: the distortion wave is the `distortion-wave` package at 0.1.2 with a local patch (`patches/`; none of it is in later releases, so an upgrade means porting it). Its colors are the site's (clay, peach, plum, sky and mineral, read from the tokens in `src/lib/wave.ts`). A hover or tap wave leaves an outline on its element that clears slowly, at the library's original pace whatever the wave's speed (`linger()` in `src/lib/wave.ts`); the elements have no border of their own. The patch adds `hairTone` and `hairLean` for that line's color: near-white on dark pages (the library's own), darker and more of the palette on light ones. It also adds `evenFade`, which fades the whole outline out together; the library otherwise wipes it away in a circle growing from the wave's origin, so the side the wave started from loses its outline first. The glow along the edge is one thickness all the way round (`uneven: 0` in the defaults of `src/lib/wave.ts`, an option the library already has): as shipped it swells and thins in a pattern that starts the same on every wave, thinnest halfway down the left edge, which reads as a round bite out of the glow. And it makes a snapshot and its corner radii follow the scale of the element's ancestors (a CSS `zoom` or a transform: it compares the element's drawn width with its laid-out one), so a scaled figure of the docs is drawn at its on-screen size, not its laid-out one. The library is left out of Vite's pre-bundling (`optimizeDeps.exclude` in `vite.config.ts`), so the dev server serves the patched file itself. After changing the patch (`pnpm patch`, `pnpm patch-commit`) the package moves to a new folder, which a running dev server only finds after a restart: re-save `vite.config.ts` and Vite restarts itself. The patch also copies only what is near the window when it snapshots a page, and waits only for images near the window, so a long page with lazy images does not stall the wave. And it keeps a sticky element where it is on the page (in the snapshot its `top` is measured from the visible part of the target, not from the window). An element the wave is to cross as one sheet needs a background of its own: one without is treated as loose content, and the wave plays on each thing inside it. An element inside `[data-no-wave]` takes no hover or click wave unless it sits in a `data-wave` element placed inside that area, and going to another page ends any wave still playing, so its snapshot never sits on the new page (`src/components/WaveEffects.tsx`); a wave that is itself carrying a change (the theme switch, a docs tab going to its page, a theme pick on the docs' figures) is left to finish. The page can be scrolled while any wave plays, which is also the patch: the wave's canvas lies in the page (`position: absolute`, fixed only over a fixed target), so it scrolls with it, and a target that reaches past the window is hidden only where its picture is (a hole cut with `clip-path`; a target wholly in the window is still hidden with `opacity`), so what scrolls into view is the real page, already changed, and not a blank. When the update itself scrolls the page (a docs tab swapping in its next page from the top), the patch moves the picture by as much, so it stays where it was in the window. Do not lock scrolling during a wave
- Icons from `react-icons/tb` (Tabler icon set)
- Styling via Tailwind classes; utility helper `cn()` from `src/lib/utils.ts`

## Admin (`/admin`)

A small CMS for projects, experience and references (books are in D1 too, but the shelf is hidden and has no editor yet).

- **Auth:** a Cloudflare Access application for `leo.dev/admin*` (team `leodotdev.cloudflareaccess.com`) gates the pages at the edge. The Worker re-verifies the Access JWT for `/admin` pages (`src/server.ts`), and every admin server function verifies it again (`requireAdmin`), reading the `Cf-Access-Jwt-Assertion` header or, for `/_serverfn` calls outside the Access path, the `CF_Authorization` cookie. `ACCESS_AUD` in `wrangler.jsonc` must hold the application's audience tag; while it is empty, production refuses `/admin` and every admin call.
- **Local dev:** `vite dev` on localhost skips the Access check (`import.meta.env.DEV`, compiled out of production builds).
- **Writes** go straight to production D1/R2; there is no draft state. Deleting a project or image does not delete its files from R2 (they are cheap and keys are never reused).
