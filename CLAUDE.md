# CLAUDE.md

## Project

Personal portfolio site for Leo Succar (leo.dev). Stack:

- **TanStack Start** (React 19) — file-based routes in `src/routes/`, server-rendered on a **Cloudflare Worker** via `@cloudflare/vite-plugin`; TypeScript strict mode
- **Tailwind CSS 4** — configured in `src/styles.css` (`@theme`), no `tailwind.config.js`; shadcn-style `src/components/ui/` primitives on **Base UI**
- **Content in Cloudflare D1** (Drizzle ORM), **images in R2**, edited at **`/admin`** (a small built-in CMS behind Cloudflare Access). Sanity was removed on 2026-11-09
- **motion** (`motion/react`) — animations
- **pnpm**, exact-pinned versions. Nothing from Vercel (no Next.js, no `vercel` CLI, no `next-*` packages); keep it that way.

## Commands

| Command | Purpose |
|---------|---------|
| `pnpm dev` | Dev server at http://localhost:3000 |
| `pnpm verify` | Typecheck + lint + production build — **run before every commit** |
| `pnpm lint` | ESLint only |
| `pnpm typecheck` | Typecheck only |
| `pnpm run deploy` | Build, check `dist/` for secrets, `wrangler deploy` |
| `pnpm preview` | Serve the production build locally (workerd) |
| `pnpm db:generate` | Generate a migration in `drizzle/migrations/` after editing `src/server/db/schema.ts` |
| `pnpm db:migrate` | Apply pending migrations to the production D1 database |
| `pnpm cf:types` | Regenerate `worker-configuration.d.ts` after editing `wrangler.jsonc` |

`src/routeTree.gen.ts` is generated by the TanStack Router plugin on `dev`/`build` (or `pnpm generate-routes`); commit it, don't edit it.

## Layout

- `src/server.ts` — Worker entry: `/images/*` from R2 (edge-cached, immutable), the `/resume` → `/resume.html` rewrite, the Access check for `/admin` pages, then TanStack Start's handler
- `src/router.tsx`, `src/client.tsx` — router and hydration entry
- `src/routes/__root.tsx` — HTML shell, meta tags, theme script, 404 page
- `src/routes/_site/index.tsx` — the home page at `/`. `/projects` (`projects.index.tsx`) renders the same page with a canonical link to `/`, and deliberately does not redirect: the old site sent `/` to `/projects` with a cached 308, so a redirect back would loop
- `src/routes/_site/` — the site's pages under a pathless `_site` layout: `projects.index.tsx`, `projects.$slug.tsx` (404 for unknown slugs), `life-calendar.tsx`, `soon.tsx`
- `src/routes/_site/work.index.tsx` — `/work`, an unlisted link (noindex, nothing links to it): the home page plus the "Recent work" section, which shows nowhere else. Its entries are hand-written in `src/lib/recent-work.ts`, not in the CMS; each can name a `logo` in `public/` (the Claude spark is `public/logo-claude.svg`), shown before its title like an experience logo, and one without shows its first letter. Its rows and the Experience list's are one component (`RowContent` in `src/components/projects/list-row.tsx`), so the two lists stay alike: change a row there, not in either list
- `src/routes/_site/work.claude*.tsx` — `/work/claude`, docs for one recent work (the Claude.com design system): a layout with five tabs (`work.claude.tsx`). The tabs and a page's chapter list are one component, `NavList` (`src/components/work/claude/nav-list.tsx`; `.nav-list` in `src/styles.css`): a plain list of names with the current one heavier, across the page for the tabs and down the side for the chapters. A tab swaps the section in place, carried by the distortion wave over the whole section, tab row included (the page does not jump to its top; if it is scrolled into the section it first glides back to the section's start, since the wave needs the page still); a chapter name glides quickly to its chapter on a spring, running a few pixels past and settling (`glideTo` in `src/lib/glide.ts`), and the one in view is marked. The tab row that sits with the theme dots at the top of the content, under the introduction, and stays at the top of the window while the page scrolls (the bar is 49px tall from 768px, about 81px on a phone; the chapter list and the chapters' `scroll-mt` are set below it), an overview (`work.claude.index.tsx`) and one page per group of topics (`work.claude.$doc.tsx`: `/atoms`, `/molecules`, `/organisms`, `/templates`, the four pages of the system's Figma file, whose grouping the docs follow). The topics are listed in `src/components/work/claude/docs.ts`. The overview opens with a strip of clips of the finished site (`src/components/work/claude/media.tsx`), streamed as HLS from Mux playback ids; they are not files in this repo. The strip drifts sideways slowly, can be dragged with the mouse and thrown, and is endless both ways (a clip out of sight on the long side moves to the other end). Below the bar at the top these pages take no hover or click wave (`data-no-wave`), except the overview's topic rows, which are marked `data-wave` and behave like the home page's list rows. "Live" topics are built in HTML and CSS (`src/components/work/claude/pages/`, controls in `specimens.tsx`); "frames" topics show frames exported from Figma (`src/lib/claude-work.json`, images in `public/work/claude/<chapter>/` as `<file>-thumb.webp` and `<file>-full.webp`). Everything in Atoms, Molecules and Organisms is live; only the Templates tab, whole pages, stays as frames. Illustrations, the footer's Anthropic mark and the logo wall's logos are SVGs exported from Figma (`public/work/claude/illustrations/`, `logos/`); illustrations are drawn dark on light, so dark themes turn them over with a CSS filter (`--cds-art-filter`). Beside the theme dots a second switch (a dot like the grid switch's, hatched) turns on the spacing view (`src/components/work/claude/spacing.tsx`): over every figure (`[data-figure]`, set by `Specimen` and `ThemeStrip`) it outlines the components' elements and hatches their padding in switch blue and the gaps and margins inside them in Clay on one canvas (only elements with a `cds-` component class and their contents count, so the figure's own padding and the docs' layout gaps are left out), and writes a strip's length on it under the pointer (on every strip with room, where nothing hovers). It is for the figures only; the site's own layout overlay is `GridSwitcher`. A figure can also be tried out by a demo cursor (`DemoCursor` in `src/components/work/claude/demo-cursor.tsx`, on every Molecules and Organisms figure that has something to try; a figure with nothing to press, like the header sizes, features, proof and the logo wall, has none; each figure's steps are listed in its page file): a small arrow follows a list of steps (a selector, optional text, hover, click, type or drag), marks what it rests on `data-state="hover"`, sends it the pointer events of a real pointer arriving (so what opens on hover opens), and clicks for real. It types into a field without focusing it (the field's box is marked `data-state="focus"`, and what the field held comes back when the steps start over or the cursor leaves), so a hover or focus style a figure relies on needs a `[data-state]` twin in `src/claude-ds.css`. Its clicks are untrusted events, which is how the clipboard-copy figure knows not to write to the visitor's clipboard. It loops, leaves the moment the visitor's pointer or focus enters the figure and returns after they go; it does not run on touch devices, off screen, or under reduced motion. A figure whose point is its responsive design sits in a `Resizable` (`resizable.tsx`): a centered box with a rounded grip on each side, dragged (or moved with the arrow keys) to narrow it, which the demo cursor also drags. The artifact uses it to show its five device sizes, each a container-query layout named by a label under the stage. The navigation figure uses it too: its cursor looks through the menus, narrows the header until it folds, opens the folded menu, and repeats. That figure follows claude.com's behavior: menus open on hover with the chevron turning up, links only change color, the other rows of an open menu dim, and the folded header has the three-line button that crosses into an X and a sheet wiped down from under the header. The topics read as chapters of one piece, visual first and with very little writing (`Section` in `src/components/work/claude/ui.tsx`). From 1024px a group's page (`work.claude.$doc.tsx`) keeps its list of chapters in the first three columns, where it stays in view while the page scrolls and marks the chapter being read, and the chapters fill the nine columns beside it; narrower, the list is a row above them. A chapter is its name (no introduction) over its blocks: each block's name, with a short note under it where one is needed, over its figures (a chapter with one block leaves the block's name off). On the Organisms page every figure is a small working copy of the real thing: from 1024px it is laid out at twelve columns' width and drawn scaled down to the nine, all by the same amount (`data-scaled` on the chapter in `work.claude.$doc.tsx`, applied in `Section`). A scaled block's figures carry a caption under them, "Scaled down", and inside a scaled figure the fluid type sizes follow the figure's width, not the window's (`--cds-vw`). Each group's page ends with a link to the next group. The overview keeps its own layout: group names in the margin, one row per topic. Keep the writing to that: a chapter's name with no introduction, and at most one short note per block (not every block needs one), about what is shown, with no measurements, spec lines or component definitions, and no docs gimmicks
- `src/claude-ds.css` — the Claude.com design system's own tokens (colors, themes, type styles). They started from its Figma file and were matched to the stylesheet claude.com ships on 2026-11-16, so production is the reference where the two differ: five themes (White, Ivory, Neutral 1, Dark 2, Dark 3), fluid type sizes with ratio leading, and production's button, input, switch and tab values (the switch is claude.com's 56px `Switch`, with hairline borders, not the smaller `ToggleSwitch` in its cookie banner). The whole site wears this palette: White in light mode and Dark 3 in dark mode (the defaults sit in `:where()` rules in this file). Its type styles and components apply inside a `.cds` box (the docs' specimens), where the site's two-type-size rule does not apply. On `/work/claude` the page itself keeps the site's theme and light switch; the five dots in the tab row pick a theme for the figures only: `ThemeProvider` (`src/components/work/claude/ui.tsx`) hands the pick to every `Specimen` as its `data-theme`. With nothing picked the figures take the page's theme, and using the site's light switch drops the pick. The dots and the spacing switch are left off the Overview tab, which has no figures. A pick is carried by the distortion wave on each figure in the window that takes it (up to four at once, the wave's limit), starting from the dot; the docs' tab row is lifted above the wave's canvas while it plays. The provider's `data-claude-page` element only marks these pages for the Clay accent. Anthropic Serif, Sans and Mono are loaded from `public/fonts/anthropic-*-variable.woff2` (files Leo supplied; `@font-face` at the top of this file) and are for the docs' specimens only. The font files are licensed, so `public/fonts/anthropic-*` is git-ignored: they deploy from the local copy and must be in place before `pnpm run deploy`, or the docs fall back to system fonts
- `src/server/content.ts` — server functions the public pages read D1 through. The home page's projects section is hidden for now (commented out in `src/components/projects/home-page.tsx`), so `getHomePage` does not read the project list; project pages at `/projects/$slug` are still live
- `src/server/db/` — Drizzle schema (`schema.ts`) and the D1 handle; migrations in `drizzle/migrations/`, the one-off Sanity import in `drizzle/seed/`
- `src/server/admin.ts` — admin server functions (CRUD, reorder, image upload), each behind `requireAdmin` (`src/server/auth/`)
- `src/routes/admin*` — the admin UI; shared editors in `src/components/admin/`
- `src/components/`, `src/lib/` (`theme.tsx` is the light/dark theme provider: dark by default, light only once a visitor switches, and the system's setting is ignored, `wave.ts` the distortion wave)
- `src/components/Navigation.tsx` — the top of every page: the name and title, Contact and the theme and grid switchers. The home page shows it as is (`HeroSection`); a page under it passes `BackButton`, which sits to the left of the name (the same pill without its label on a phone, to leave room for the name and title). The pill slides in, moving the name over; on the page that follows, a header without a Back button shows the last one sliding shut (`BackButtonExit`), so the name travels back the same way
- `src/components/GridSwitcher.tsx` — the dot next to the theme switcher; toggles `html.show-grid`, the layout overlay (element outlines and the page's columns) defined at the end of `src/styles.css`
- `old/` (git-ignored) — the pre-migration Next.js/Sanity app and content backup; not part of the site

## Deployment and content freshness

- The site deploys as a Cloudflare Worker named `leodotdev` on the custom domain `leo.dev` (`wrangler.jsonc`; Cloudflare manages its DNS record); ship with `pnpm run deploy`. Static files in `public/` are served before the Worker runs (`html_handling: "none"`, so `/resume.html` stays reachable as is).
- Pages render per request and read D1 directly, so **edits made at `/admin` show up on the next page load**, with no rebuild or deploy.
- `pnpm dev` uses the **production** D1 database and R2 bucket (`remote: true` in `wrangler.jsonc`), like mdc: local admin edits are live.
- Workers runtime only: no Node `fs`; `nodejs_compat` is on. Use `cloudflare:workers` for `env`/`waitUntil`.

## Conventions

- Path alias `@/*` → `src/*` (configured in `tsconfig.json`)
- Routes: `createFileRoute`, data in `loader` via server functions; internal links use TanStack `Link` (`to="/projects/$slug"` + `params`), external links and static files use plain `<a>`
- Images: stored as `Img` records (`src/lib/image.ts`): WebP at 320/960/1920px in R2, named `<base>-<width>.webp`. Render with plain `<img {...imageProps(img, { maxWidth })}>` and pass `sizes`. Plain strings (files in `public/`, like the experience logos) pass through. Admin uploads are resized in the browser (`src/lib/resize.ts`); SVG uploads are refused (same-origin script risk)
- Fonts: `@fontsource-variable/inter` (body) and `@fontsource-variable/playfair-display` (`font-playfair`), imported in `src/styles.css`, and Paper Mono (`font-mono`; `public/fonts/paper-mono-variable.woff2`, open source, licence beside it) for all 12px text
- Type scale: only `text-xs` (12px, which also sets Paper Mono) and `text-base` (16px, Inter) exist; other `text-<size>` classes are no-ops
- Colors: the whole site wears the Claude.com design system's palette (`src/claude-ds.css`; the site's tokens in `src/styles.css` point at it): the White theme in light mode and Dark 3 in dark mode. Tailwind's own palette is switched off, so `blue-500`, `zinc-200` and the like are no-ops. Use the accent (`text-tint`: the system's switch blue, `#2c84db`, everywhere except `/work/claude`, where it is Clay), Clay itself (`clay`) and the secondary colors (`heather`, `cactus`, `peach`, `plum`, `mineral`, `sky`, as in `bg-peach/40`), `error`, the greys (`gray`, `gray-2` … `gray-6`) and the roles built on them (`bg-background`, `bg-card`, `text-muted-foreground`, `border-border`). The neutrals follow the theme, so `dark:` variants are only needed for a tint's opacity. The layout overlay is the palette's switch blue on every page, `/work/claude` included (`--color-grid`)
- Formatting: Prettier, no semicolons (`pnpm format`; `pnpm check` to verify)
- Titles: a title, name or label joins its parts with `&`, not "and" ("Headers & Footer", "Checkbox, Radio & Switch"). Sentences keep "and"
- Focus: one rule at the end of the base styles in `src/styles.css` outlines whatever has keyboard focus (2px, the accent color, 2px off). Do not add focus rings to components; a box that clips its children (`overflow-hidden`, a scrolling row) needs 4px of padding for the outline
- Text blocks on the docs pages end on a column edge: `max-w-cols-9` (9 of 12 columns, 6 of 8 on a tablet). The layout overlay's columns have 24px gutters and 48px margins (24px on a phone)
- Waves: the distortion wave is the `distortion-wave` package at 0.1.2 with a local patch (`patches/`; none of it is in later releases, so an upgrade means porting it). Its colors are the site's (clay, peach, plum, sky and mineral, read from the tokens in `src/lib/wave.ts`). A hover or tap wave leaves an outline on its element that clears slowly, at the library's original pace whatever the wave's speed (`linger()` in `src/lib/wave.ts`); the elements have no border of their own. The patch adds `hairTone` and `hairLean` for that line's color: near-white on dark pages (the library's own), darker and more of the palette on light ones. It also adds `evenFade`, which fades the whole outline out together; the library otherwise wipes it away in a circle growing from the wave's origin, so the side the wave started from loses its outline first. The glow along the edge is one thickness all the way round (`uneven: 0` in the defaults of `src/lib/wave.ts`, an option the library already has): as shipped it swells and thins in a pattern that starts the same on every wave, thinnest halfway down the left edge, which reads as a round bite out of the glow. And it makes a snapshot and its corner radii follow a CSS `zoom` on the element's ancestors, so a scaled figure of the docs is drawn at its on-screen size, not its laid-out one. The library is left out of Vite's pre-bundling (`optimizeDeps.exclude` in `vite.config.ts`), so the dev server serves the patched file itself. After changing the patch (`pnpm patch`, `pnpm patch-commit`) the package moves to a new folder, which a running dev server only finds after a restart: re-save `vite.config.ts` and Vite restarts itself. The patch also copies only what is near the window when it snapshots a page, and waits only for images near the window, so a long page with lazy images does not stall the wave. And it keeps a sticky element where it is on the page (in the snapshot its `top` is measured from the visible part of the target, not from the window). An element the wave is to cross as one sheet needs a background of its own: one without is treated as loose content, and the wave plays on each thing inside it. An element inside `[data-no-wave]` takes no hover or click wave unless it sits in a `data-wave` element placed inside that area, and going to another page ends any wave still playing, so its snapshot never sits on the new page (`src/components/WaveEffects.tsx`); a wave that is itself carrying a change (the theme switch, a docs tab going to its page, a theme pick on the docs' figures) is left to finish, and while one plays the page cannot be scrolled (`holdScroll` in `src/lib/wave.ts`), since the wave shows a picture of what was on screen where it was
- Icons from `react-icons/tb` (Tabler icon set)
- Styling via Tailwind classes; utility helper `cn()` from `src/lib/utils.ts`

## Admin (`/admin`)

A small CMS for projects, experience and references (books are in D1 too, but the shelf is hidden and has no editor yet).

- **Auth:** a Cloudflare Access application for `leo.dev/admin*` (team `leodotdev.cloudflareaccess.com`) gates the pages at the edge. The Worker re-verifies the Access JWT for `/admin` pages (`src/server.ts`), and every admin server function verifies it again (`requireAdmin`), reading the `Cf-Access-Jwt-Assertion` header or, for `/_serverfn` calls outside the Access path, the `CF_Authorization` cookie. `ACCESS_AUD` in `wrangler.jsonc` must hold the application's audience tag; while it is empty, production refuses `/admin` and every admin call.
- **Local dev:** `vite dev` on localhost skips the Access check (`import.meta.env.DEV`, compiled out of production builds).
- **Writes** go straight to production D1/R2; there is no draft state. Deleting a project or image does not delete its files from R2 (they are cheap and keys are never reused).
