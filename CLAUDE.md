# CLAUDE.md

## Project

Personal portfolio site for Leo Succar (leo.dev). Stack:

- **TanStack Start** (React 19) — file-based routes in `src/routes/`, server-rendered on a **Cloudflare Worker** via `@cloudflare/vite-plugin`; TypeScript strict mode
- **Tailwind CSS 4** — configured in `src/styles.css` (`@theme`), no `tailwind.config.js`; shadcn-style `src/components/ui/` primitives on **Base UI**
- **Content in Cloudflare D1** (Drizzle ORM), **images in R2**, edited at **`/admin`** (a small built-in CMS behind Cloudflare Access). Sanity was removed on 2026-11-09
- **motion** (`motion/react`) — animations
- **pnpm**, exact-pinned versions. Nothing from Vercel (no Next.js, no `vercel` CLI, no `next-*` packages); keep it that way.

## Commands

| Command | Purpose |
|---------|---------|
| `pnpm dev` | Dev server at http://localhost:3000 |
| `pnpm verify` | Typecheck + lint + production build — **run before every commit** |
| `pnpm lint` | ESLint only |
| `pnpm typecheck` | Typecheck only |
| `pnpm run deploy` | Build, check `dist/` for secrets, `wrangler deploy` |
| `pnpm preview` | Serve the production build locally (workerd) |
| `pnpm db:generate` | Generate a migration in `drizzle/migrations/` after editing `src/server/db/schema.ts` |
| `pnpm db:migrate` | Apply pending migrations to the production D1 database |
| `pnpm cf:types` | Regenerate `worker-configuration.d.ts` after editing `wrangler.jsonc` |

`src/routeTree.gen.ts` is generated by the TanStack Router plugin on `dev`/`build` (or `pnpm generate-routes`); commit it, don't edit it.

## Layout

- `src/server.ts` — Worker entry: `/images/*` from R2 (edge-cached, immutable), the `/resume` → `/resume.html` rewrite, the Access check for `/admin` pages, then TanStack Start's handler
- `src/router.tsx`, `src/client.tsx` — router and hydration entry
- `src/routes/__root.tsx` — HTML shell, meta tags, theme script, 404 page. The page is a 960px column in the middle of the window with no lines down its sides (Leo, 2026-11-19, "let's try": it had a border on each side from 961px). A box that should reach the window's edges takes the `bleed` utility (`src/styles.css`): margins out to the window and padding back in, so its contents keep to the column; `--bleed-pad` adds side padding of its own. The docs' section, its sticky bar, its introduction's band and the overview's strip of clips use it. Every section is as wide as the window in this sense, so the lines between sections are too (Leo, 2026-11-19): `<Separator bleed />` between a page's sections, and `rule-t` / `rule-b` (also in `src/styles.css`) in place of `border-t` / `border-b` on a section, which draw the line across the window without changing the section's own box. A line inside a card or a list stays a plain border
- `src/routes/_site/index.tsx` — the home page at `/`. `/projects` (`projects.index.tsx`) renders the same page with a canonical link to `/`, and deliberately does not redirect: the old site sent `/` to `/projects` with a cached 308, so a redirect back would loop

## Deployment and content freshness

- The site deploys as a Cloudflare Worker named `leodotdev` on the custom domain `leo.dev` (`wrangler.jsonc`; Cloudflare manages its DNS record); ship with `pnpm run deploy`. Static files in `public/` are served before the Worker runs (`html_handling: "none"`, so `/resume.html` stays reachable as is).
- Pages render per request and read D1 directly, so **edits made at `/admin` show up on the next page load**, with no rebuild or deploy.
- `pnpm dev` uses the **production** D1 database and R2 bucket (`remote: true` in `wrangler.jsonc`), like mdc: local admin edits are live.
- Workers runtime only: no Node `fs`; `nodejs_compat` is on. Use `cloudflare:workers` for `env`/`waitUntil`.

## Conventions

- Path alias `@/*` → `src/*` (configured in `tsconfig.json`)
- Routes: `createFileRoute`, data in `loader` via server functions; internal links use TanStack `Link` (`to="/projects/$slug"` + `params`), external links and static files use plain `<a>`
- Images: stored as `Img` records (`src/lib/image.ts`): WebP at 320/960/1920px in R2, named `<base>-<width>.webp`. Render with plain `<img {...imageProps(img, { maxWidth })}>` and pass `sizes`. Plain strings (files in `public/`, like the experience logos) pass through. Admin uploads are resized in the browser (`src/lib/resize.ts`); SVG uploads are refused (same-origin script risk)
- Fonts: `@fontsource-variable/inter` (body) and `@fontsource-variable/playfair-display` (`font-playfair`), imported in `src/styles.css`, and Paper Mono (`font-mono`; `public/fonts/paper-mono-variable.woff2`, open source, licence beside it) for all 12px text
- Type scale: only `text-xs` (12px, which also sets Paper Mono) and `text-base` (16px, Inter) exist; other `text-<size>` classes are no-ops. Both have lines a whole number of pixels tall (17px and 24px): a fractional line height leaves everything under it between pixels, and its borders and rules are then drawn soft
- Colors: the whole site wears the Anthropic.com design system's palette (Leo, 2026-11-20: "it has more colors"; `src/anthropic-ds.css`, whose primitives sit on the root; the site's tokens in `src/styles.css` point at it): the White theme in light mode and Slate in dark mode. Before that day it wore the Claude.com palette, which has the same grays. Tailwind's own palette is switched off, so `blue-500`, `zinc-200` and the like are no-ops. Use the accent (`text-tint`: the system's focus blue, `#154c92` light and `#90c3f6` dark, everywhere except `/work/claude`, where it is Clay), Clay itself (`clay`) and the fifteen other secondary colors (`fig`, `orchid`, `poppy`, `coral`, `peach`, `pencil`, `oat`, `olive`, `matcha`, `mineral`, `cactus`, `sky`, `cloud`, `plum`, `heather`, as in `bg-peach/40`), `error`, the greys (`gray`, `gray-2` … `gray-6`) and the roles built on them (`bg-background`, `bg-card`, `text-muted-foreground`, `border-border`). The neutrals follow the theme, so `dark:` variants are only needed for a tint's opacity. The layout overlay is the palette's focus blue on every page, `/work/claude` included (`--color-grid`)
- Formatting: Prettier, no semicolons (`pnpm format`; `pnpm check` to verify)
- Titles: a title, name or label joins its parts with `&`, not "and" ("Headers & Footer", "Checkbox, Radio & Switch"). Sentences keep "and"
- Lists in copy take the serial (Oxford) comma: "navigation, prompt suggestions, and lists"
- Focus: one rule at the end of the base styles in `src/styles.css` outlines whatever has keyboard focus (2px, the accent color, 2px off). Do not add focus rings to components; a box that clips its children (`overflow-hidden`, a scrolling row) needs 4px of padding for the outline
- Text blocks on the docs pages end on a column edge: `max-w-cols-9` (9 of 12 columns, 6 of 8 on a tablet). The captions under the docs' titles run wider, `max-w-cols-11` (11 of 12, 7 of 8 on a tablet; Leo, 2026-11-19). The layout overlay's columns have 24px gutters and 48px margins (24px on a phone)
- Waves: the distortion wave is the `distortion-wave` package at 0.1.2 with a local patch (`patches/`; none of it is in later releases, so an upgrade means porting it). Its colors are the site's: the Anthropic palette's eight deeper secondary colors in hue order, poppy, clay, pencil, olive, mineral, sky, plum, and fig, looping back to poppy (read from the tokens in `src/lib/wave.ts`; the library takes eight). A hover or tap wave leaves an outline on its element that clears slowly, at the library's original pace whatever the wave's speed (`linger()` in `src/lib/wave.ts`); the elements have no border of their own. The patch adds `hairTone` and `hairLean` for that line's color: near-white on dark pages (the library's own), darker and more of the palette on light ones. It also adds `evenFade`, which fades the whole outline out together; the library otherwise wipes it away in a circle growing from the wave's origin, so the side the wave started from loses its outline first. The glow along the edge is one thickness all the way round (`uneven: 0` in the defaults of `src/lib/wave.ts`, an option the library already has): as shipped it swells and thins in a pattern that starts the same on every wave, thinnest halfway down the left edge, which reads as a round bite out of the glow. And it makes a snapshot and its corner radii follow the scale of the element's ancestors (a CSS `zoom` or a transform: it compares the element's drawn width with its laid-out one), so a scaled figure of the docs is drawn at its on-screen size, not its laid-out one. In WebKit it also copies a uniform scale from the top-left corner (how `Scaled` shrinks a figure) as an equal `zoom`: WebKit draws the picture onto its canvas in tiles, and a rounded, clipped box inside a transform was clipped to each tile, so every figure showed a vertical line, and its rounded edge again, during a wave in Safari (Leo, 2026-11-19). And it lays the picture out at the screen's pixel ratio in WebKit too, not only in Chromium: WebKit draws an SVG image it scales up without any of its box-shadows, so the figures' rings (an inset shadow) vanished for the length of a docs tab's wave in Safari and came back at hand-back (Leo, 2026-11-20). Also from that day: WebKit decodes the pictures inside an SVG image only once it is first drawn, so the patch draws the copy once, waits two frames, and draws it again (without that, a video's frame and the pages' photos were missing from Safari's pictures); a box scrolled on the page (the overview's clip strip, a template's window) keeps its scroll in the copy, its children moved by as much (the copy has no scroll of its own, so the strip jumped back to its start for the length of a theme switch's wave); and a video is copied as its current frame, drawn only as large as it is shown and as a JPEG, or as its poster where there is no frame to draw. A picture from a host that refuses this site's origin cannot be copied at all: the overview strip's three stills, from the studio's `cdn.sanity.io`, show as their empty tiles in a wave. The library is left out of Vite's pre-bundling (`optimizeDeps.exclude` in `vite.config.ts`), so the dev server serves the patched file itself. After changing the patch (`pnpm patch`, `pnpm patch-commit`) the package moves to a new folder, which a running dev server only finds after a restart: re-save `vite.config.ts` and Vite restarts itself. The patch also copies only what is near the window when it snapshots a page, and waits only for images near the window, so a long page with lazy images does not stall the wave. And it keeps a sticky element where it is on the page (in the snapshot its `top` is measured from the visible part of the target, not from the window). An element the wave is to cross as one sheet needs a background of its own: one without is treated as loose content, and the wave plays on each thing inside it. An element inside `[data-no-wave]` takes no hover or click wave unless it sits in a `data-wave` element placed inside that area, and going to another page ends any wave still playing, so its snapshot never sits on the new page (`src/components/WaveEffects.tsx`); a wave that is itself carrying a change (the theme switch, a docs tab going to its page, a theme pick on the docs' figures) is left to finish. The page can be scrolled while any wave plays, which is also the patch: the wave's canvas lies in the page (`position: absolute`, fixed only over a fixed target), so it scrolls with it, and a target that reaches past the window is hidden only where its picture is (a hole cut with `clip-path`; a target wholly in the window is still hidden with `opacity`), so what scrolls into view is the real page, already changed, and not a blank. When the update itself scrolls the page (a docs tab swapping in its next page from the top), the patch moves the picture by as much, so it stays where it was in the window. Do not lock scrolling during a wave. The waves switch (`WaveSwitcher`; `wavesOn`, `setWaves` and `subscribeWaves` in `src/lib/wave.ts`) turns every wave off sitewide (Leo, 2026-11-20): it is on by default, except for visitors whose system asks for reduced motion, for whom it starts off; either can switch it, and the pick is stored in the browser (`localStorage` key `waves`). Off, `wave()` applies the change it would have carried at once (the light switch, a docs tab, a theme pick), no hover or tap wave plays, and the library is not even loaded; switching off ends any wave playing, in every open tab (a wave waiting on another checks again before it starts); on, it plays the full wave whatever the system's motion setting (`reducedMotion: false`). Switching waves back on sends one wave over the page from the ball
- Corners: every radius is drawn as a squircle (`corner-shape: squircle` on everything, in the base styles of `src/styles.css`). Tailwind's `rounded-full` is put back to round there, but a fully round shape whose radius is set in CSS (a pill's `96px`, a dot's `50%`) needs `corner-shape: round` beside it, or Chromium draws it as a soft-cornered box (the research table's more buttons were, until 2026-11-21)
- Spring: what comes up from the bottom of the window springs up with a bounce (Leo, 2026-11-23): the toasts and the back-to-top pill start below the window's edge, run about a tenth past where they rest, and settle; leaving, they drop back quickly with no bounce. The curve is a real spring sampled into `linear()` (`--ease-spring` with `--spring-time` in `src/styles.css`: 0.5s, bounce 0.4; easeOutBack where `linear()` is not supported). The rows Show more lets into a home section come down from under the row above them, one after another on it, and the rows Show less sends away go back up under it, the last first, before the list shortens (`reveal(i)` from `useShowMore`, `[data-enter]` / `[data-leave]`); on touch with waves on, the tap's wave carries that change as before and the rows do not also stagger. Use this spring for anything else that pops up from the bottom
- Icons from `react-icons/tb` (Tabler icon set)
- Styling via Tailwind classes; utility helper `cn()` from `src/lib/utils.ts`

## Admin (`/admin`)

A small CMS for projects, experience and references (books are in D1 too, but the shelf is hidden and has no editor yet).

- **Auth:** a Cloudflare Access application for `leo.dev/admin*` (team `leodotdev.cloudflareaccess.com`) gates the pages at the edge. The Worker re-verifies the Access JWT for `/admin` pages (`src/server.ts`), and every admin server function verifies it again (`requireAdmin`), reading the `Cf-Access-Jwt-Assertion` header or, for `/_serverfn` calls outside the Access path, the `CF_Authorization` cookie. `ACCESS_AUD` in `wrangler.jsonc` must hold the application's audience tag; while it is empty, production refuses `/admin` and every admin call.
- **Local dev:** `vite dev` on localhost skips the Access check (`import.meta.env.DEV`, compiled out of production builds).
- **Writes** go straight to production D1/R2; there is no draft state. Deleting a project or image does not delete its files from R2 (they are cheap and keys are never reused).
