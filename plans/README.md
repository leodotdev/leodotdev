## Findings considered and rejected

(Recorded so nobody re-audits them.)

- **Dual scroll listeners racing on localStorage** (`projects-wrapper.tsx` vs `hooks/useScrollPosition.ts`): the hook has zero importers — it's dead code (deleted in 004), not a race.
- **"Sanity client recreated on every render"**: all client-component instances are module-scope constants; the duplication is config debt (plan 006), not a render-loop cost.
- **"`/api/photos` always 500s on Cloudflare"** as originally reported: the route is statically prerendered at build time (build output: `○ /api/photos`), so it "works" as a frozen snapshot — the real issue is that its only consumer is dead code (handled in 004).
- **`console.error` in the photos route as info disclosure**: by-design logging; route is deleted in 004 anyway.
- **`tsconfig target: es5`**: Next.js compiles via SWC with its own targets; changing this has near-zero effect. Not worth a plan.
- **Lightbox render-performance memoization** (React.memo on thumbnails etc.): micro-optimization on a personal site; no measured problem.
- **ESLint 9 / eslint pin migration**: speculative; nothing is broken. Revisit with a Next.js major upgrade.
- **Next 15/React 19/Sanity major upgrades**: real cost, unclear benefit for a working static site; deliberate non-goal until something forces it.
- **Hardcoded Sanity project ID as a "secret"**: Sanity project IDs are public by design; only the duplication mattered (plan 006).
